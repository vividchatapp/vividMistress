# Vivid Mistress

A lightweight, self-hosted single-chat web server with voice (TTS), role-playing personalities, and hands-free auto-continue. One Go binary, no Node.js, no Docker, no Python.

Optimized for the **Raspberry Pi** (ARMv6/ARM64) but builds for Windows, macOS, Linux, and FreeBSD.

---

## Features

- **Single Always-On Chat** — One persistent conversation per browser, no sidebar or account management.
- **Voice (Narrator Mode)** — Replies are spoken aloud via Microsoft Edge's online TTS. Choose from 36 voices (British, American, Australian, Japanese, Indian, and more) and adjust speed 1–9.
- **Role-Playing Personalities** — Load `.txt` role files from a `roles/` folder. Switch roles live by typing `role [n]`.
- **Auto-Continue ("Pushing")** — After a voice reply finishes, the chat automatically sends "continue" so the conversation keeps going hands-free. Configurable delay, stop/start, and a 3-push safety cap.
- **Suggestion Buttons** — Up to 5 clickable reply buttons generated by the LLM. Adjust the count live with `buttons [n]`.
- **Text On/Off** — Hide the narration bubbles while keeping the voice and buttons (`text on` / `text off`).
- **Built-In Text Commands** — `help`, `status`, `role`, `voice`, `speed`, `delay`, `stop`, `start`, `buttons`, `text`, `clear` — all handled locally, never sent to the LLM.
- **Per-Browser Client ID** — Each browser gets its own isolated settings and conversation via a localStorage ID.
- **Zero External Runtime Dependencies** — Frontend (HTML/CSS/JS) embedded directly into the Go binary via `//go:embed`.
- **Flat-File JSON Persistence** — No CGO, no SQLite. Data stored as JSON files on disk.

## Pre-built Executables

Ready-to-run binaries for all supported platforms are in the [`executables/`](executables/README.md) folder, organized by OS/architecture.

To rebuild all of them from source, run `build_all.bat` or `build_all.ps1` inside the `executables/` folder.

## Build

### Local (current platform)

```bash
go build -o server .
```

### Cross-compile (from Windows/macOS/Linux)

```bash
# Raspberry Pi Zero W / Pi 1 (ARMv6)
GOOS=linux GOARCH=arm GOARM=6 CGO_ENABLED=0 go build -ldflags="-s -w" -o server ./cmd/server

# Raspberry Pi 3 / 4 (64-bit)
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -ldflags="-s -w" -o server ./cmd/server

# Windows x64
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-s -w" -o server.exe ./cmd/server
```

All 12 platform combinations are covered by the `executables/build_all.bat` and `executables/build_all.ps1` scripts.

## Run

```bash
./server -addr :8080 -data ./data -roles ./roles
```

| Flag       | Default     | Description                                          |
|------------|-------------|------------------------------------------------------|
| `-addr`    | `:8080`     | HTTP listen address                                  |
| `-data`    | `./data`    | Data directory for JSON storage                      |
| `-roles`   | `roles`     | Directory containing role `.txt` files               |
| `-model`   | `gemma4:31b` | Default Ollama model name                           |
| `-llm-dump`| *(empty)*   | If set, directory where raw LLM requests/responses are dumped |

Open `http://localhost:8080` in a browser.

## HTTP API

| Method | Path                          | Description                                    |
|--------|-------------------------------|------------------------------------------------|
| GET    | `/`                           | Serves the embedded single-page app            |
| GET    | `/api/session`                | Get/create the conversation for this browser   |
| POST   | `/api/chat`                   | Send a message (or run a command)              |
| POST   | `/api/chat/regenerate`        | Regenerate the last assistant reply            |
| GET    | `/api/chat/suggestions`       | Get suggestion buttons for the last reply      |
| GET    | `/api/providers`              | List configured LLM backends                   |
| POST   | `/api/providers`              | Add/update a provider endpoint                 |
| PUT    | `/api/providers/{id}`         | Update a provider                              |
| DELETE | `/api/providers/{id}`         | Delete a provider                              |
| GET    | `/api/models`                 | Fetch available models from a provider         |
| GET    | `/api/system-prompts`         | List named system prompts                      |
| POST   | `/api/system-prompts`         | Add/update a named system prompt               |
| DELETE | `/api/system-prompts/{id}`    | Delete a named system prompt                   |
| GET    | `/api/settings`               | Get global app settings                        |
| PUT    | `/api/settings`               | Save global app settings                       |
| GET    | `/api/voice`                  | Get current voice setting                      |
| PUT    | `/api/voice`                  | Set voice, voice name, and speed               |
| POST   | `/api/voice/speak`            | On-demand TTS (speak arbitrary text)           |
| GET    | `/api/conversations`          | List conversation threads                      |
| POST   | `/api/conversations`          | Create a new conversation thread               |
| DELETE | `/api/conversations`          | Delete ALL conversation threads                |
| GET    | `/api/conversations/{id}`     | Fetch full history for a thread                |
| PUT    | `/api/conversations/{id}`     | Update title/settings/messages                 |
| DELETE | `/api/conversations/{id}`     | Delete a conversation thread                    |

## Data Storage Layout

```
data/
├── providers.json                          # LLM backend endpoints (shared)
└── clients/
    └── <client-id>/
        ├── settings.json                   # Per-browser app settings
        ├── system_prompts.json             # Named system prompts
        └── conversations/
            └── <conversation-id>.json      # One file per chat thread
```

A default Ollama provider pointing at `https://api.ollama.com` is created on first run with an empty API key — add your key to `data/providers.json` for online Ollama, or point `base_url` at a local instance (no key needed).

## Chat Commands

Type these directly in the chat. They are handled locally and never sent to the LLM.

| Command         | Description                                                  |
|-----------------|--------------------------------------------------------------|
| `help`          | Show the command list                                        |
| `status`        | Show current voice, role, speed, delay, buttons              |
| `role`          | List available roles                                         |
| `role [n]`      | Switch to that role (e.g. `role 2`)                          |
| `voice`         | List available voices                                        |
| `voice [n]`     | Switch to that voice (e.g. `voice 5`)                        |
| `speed [n]`     | Set voice speed 1–9 (3 = 1.3x, 5 = 1.5x; default 3)         |
| `delay [n]`     | Pause after voice reply before pushing "continue" (seconds)  |
| `stop`          | Stop auto-pushing messages                                   |
| `start`         | Start auto-pushing messages                                  |
| `buttons [n]`   | Set suggestion buttons per reply, 1–5 (default 5)            |
| `text on/off`   | Show or hide the narration text (voice + buttons unaffected) |
| `clear`         | Clear the conversation context (keeps your role)             |

## Roles

Roles are plain `.txt` files in the `roles/` directory. Each file's content becomes the system prompt for the LLM. The file name (without `.txt`) is the role name.

Example `roles/Default.txt`:
```
You are a friendly, lightly proactive companion...
```

Switch roles live with `role [n]` — the change takes effect on the next message.
